# AI Book

让读者既能解释系统的一次运行，也能动手改变一个条件，判断结果为什么变化。默认使用自然、直接的简体中文；尊重用户指定的语言、篇幅、格式和既有项目约定。

本 Skill 从李博杰《深入理解 AI Agent：设计原理与工程实践》的正文和实验中提炼教学方法，适用于其他技术主题。它不要求复刻作者措辞、沿用原书目录、使用 Python 或绑定任何模型供应商。来源与观察边界见 [references/sources.md](references/sources.md)。

## 开始工作

先判断交付物：整本书、单章、实验、在线阅读网站，还是现有内容的改写。沿用已知读者基础、主题范围与产物路径；只有缺失信息会改变工作方向时才询问。

若有代码仓库，先读项目约定、构建入口和相关实现，核对文档命令是否真实存在。若只有主题，先选一个贯穿当前范围的小任务和最小可运行系统。不要为了演示某个技术，把用户的现有架构换成另一套系统。

按需要读取：

- 编排目录、写正文或改写章节：读 [references/writing.md](references/writing.md)。
- 生成在线书籍、章节 HTML 或调整阅读页面：读 [references/web-reading.md](references/web-reading.md)，按交付范围落实布局、排版、交互与验收。
- 设计实验、实现教学代码或完善实验 README：读 [references/labs.md](references/labs.md)。
- 需要校准讲解粒度、代码形态及结论措辞：读 [references/worked-example.md](references/worked-example.md)，它是原创的跨主题示例。
- 需要解释本 Skill 的来源或重新核对原书：读 [references/sources.md](references/sources.md)。日常写作不必重新下载原书。

## 组织知识与实现

先用一句话说明读者将能解释或完成什么，再找出实现这一能力必需的概念。整本书按依赖关系推进：先建立最小系统，再因其实际限制引入后续机制。单章可直接进入相关问题，无需每次重建全书背景。

围绕具体输入讲清：系统拿到什么、状态存在哪里、谁调用谁、条件分支如何选择、结果交给谁、何时结束。概念、图、简化代码、实际实现和实验使用一致的名称。

正文可以使用短小伪代码，但须明确标注不能直接运行。实验提供真实文件和命令。引用实现片段时标注路径与符号，解释关键状态变化和设计原因；对重要循环、边界检查和失败分支逐句展开，普通样板代码可合并说明。

在需要检验判断的位置安排实验。先观察一条轨迹，再比较一个变化条件；实现复杂度随教学需要增加。不要把所有工程扩展提前塞进第一个示例。

## 在线阅读页面

在线书籍采用书籍首页和章节阅读页，建立清楚的章节导航、正文与小节提纲层级。颜色、字体、留白、代码、图表和移动端适配遵循网页阅读指南。完整阅读器的主题、字号、专注模式、阅读位置和笔记功能须实际实现并验证；单章 HTML 按需缩减。保持一份书稿来源，图形展示适配不能改变实验数据或机制含义。

## 以证据约束结论

区分机制推导、预期现象、示意数据、上游历史结果与本次实测。没有运行时，给出运行方法和验收条件，不补造输出。离线固定响应只证明流程，不能证明模型能力；服务不可用与任务失败分别记录。

为主要结论保留可追溯依据：源码符号、原始运行记录、官方文档或研究来源。涉及版本、性能和产品能力时，重新核对适用条件。原书是写法参考，不是其他技术事实的依据。

若实验与预期不符，先检查控制变量、输入、验证器和轨迹；依据证据收窄或修改结论。有限样本允许得出“尚不能判断”。

## 交付前检查

- 正文能否让读者跟踪一次输入到输出，并解释至少一个关键边界？
- 实验的入口、参数、依赖、输出位置和成功条件是否与实际代码一致？
- 对照是否回答章节问题，结果是否包含失败、额外开销及适用范围？
- 所有本地引用、图片和命令是否可定位？已运行验证与未运行部分是否分开说明？
- 网页交付是否覆盖实际范围内的视觉、移动端、交互、无障碍和部署路径？是否区分源码检查与浏览器实测？
- 删除重复介绍、空泛总结和装饰性类比；保留会影响读者判断的细节。

交付用户请求的文件和简短验证说明。仅当用户要求发布、部署或上传时执行相应操作；本 Skill 本身不授权外部写入。
